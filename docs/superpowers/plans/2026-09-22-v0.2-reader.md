# V0.2 Reader Implementation Plan

**Goal:** 落实技术设计第 18 节的 V0.2 功能，保留现有阅读主题与离线使用能力。

**Architecture:** markdown-it 负责源码映射和公式，Webview 负责 Mermaid 和正文交互；Extension 负责源码定位及按 URI 持久化 TOC。现有技术设计与本次实现请求作为范围依据。

**Tech Stack:** TypeScript、VS Code CustomTextEditor、markdown-it、Mermaid、KaTeX、Vitest、Playwright。

## 实现顺序

- [x] 渲染器：补段落、列表、引用、表格、代码块的零基行号；KaTeX 支持 `$...$` / `$$...$$`；Mermaid 输出保留源码的容器。错误不阻断正文，代码与转义美元符号不解析公式。
- [x] Webview：标题提供 Edit 和 Copy Heading Link（复制 `#` + 编码后的 slug）；双击正文最近的源码块定位，排除链接、按钮、表单；TOC 子树折叠及状态恢复。
- [x] Extension：同组打开源码、校验并限制行号、设置 selection 并 reveal；TOC 可见性与折叠状态按 URI 保存在 workspaceState，上限 100 份，打开的分屏独立。
- [x] 离线资源：打包 Mermaid、KaTeX 样式字体；保持脚本 CSP 严格，生成样式使用 nonce；覆盖图表错误和刷新竞态。
- [x] 高亮：迁移 Shiki；验证未知语言转义和 Copy code。
- [x] 文档与验证：更新中英文 README、CHANGELOG；运行 `npm run check`，并用真实浏览器检查公式、图表、定位与状态交互。

## 验证方式

每组行为先补测试、运行确认失败，再实现并通过测试。渲染器检查行号及安全边界；ReaderApp 检查事件和持久化；Provider 检查 VS Code 定位与关闭/重开。浏览器使用实际 Webview HTML、CSP 与构建产物，验证 SVG、公式字体和离线资源加载。

## 决策

渲染接口改为异步，按需加载 Shiki grammar，复用 DocumentSession 的 revision 校验；保留工作区现有 package-lock.json 的扩展名称修正。当前任务实现代码和文档，不执行 Marketplace 发布。

## 最终实现细节

- 公式及 Shiki 生成样式转换为 CSS 类，正文通过 nonce 授权样式表。
- Mermaid 在 `sandbox="allow-scripts"` 的 srcdoc iframe 中生成图片；该 iframe 不授予同源能力、网络访问、导航父页面或 VS Code API。主页面读取本地 bundle 后经消息传入，脚本使用 nonce；由于 srcdoc 继承 CSP，父页面允许 Mermaid 所需的内联样式。主页面校验消息来源。
- Copy Heading Link 复制本文档编码锚点；源码定位使用 Markdown 块起始行。
- 审查修复：KaTeX 宏按每次文档渲染隔离；独立公式保留源码行；目录抽屉正确恢复键盘焦点；语言标签转义；标题查找不与页面控件 ID 冲突。
